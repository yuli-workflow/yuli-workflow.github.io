Yuli Email Ops

A private tool that reads and sorts its owner's own Gmail inboxes to produce a daily triage summary.

What it does

Yuli Email Ops is a personal automation script run by its owner on their own computer. It connects to the owner's own Gmail accounts and reads recent messages so it can produce a short daily summary answering two questions:

  • Which of today's emails actually require the owner's personal attention?
  • Which online services are still tied to an old email address that should be migrated?

The goal is to reduce the number of emails the owner has to read and judge manually each day.

Who can use it

This application is not a product and is not offered to the public. It has exactly one user: its owner, who authorizes access to their own mailboxes. There is no sign-up, no user accounts, and no third-party access.

What access it requests

Three scopes, each held as a separate token and used for one task:

  • gmail.readonly: reading messages for the daily summary
  • gmail.modify: adding the owner's own sorting labels, from a fixed list of five
  • gmail.compose: placing reply drafts in the owner's Drafts folder

Google does not offer narrower scopes for labels or drafts, so the last two technically permit more. The application's code refuses sending, deleting, archiving and removing labels before any request is made. That is a control in the code, not a limit set by Google; the Privacy Policy describes it in full.

Where the data goes

Messages are retrieved on the owner's own computer, where each one is converted into a structured record. The step that decides which messages matter is not local: those records are sent to Claude, a large language model operated by Anthropic PBC, which assigns each one a priority.

The records sent to Anthropic contain pseudonymous identifiers, labels from fixed lists, monetary amounts, dates, counts and true/false flags. They do not contain message bodies, subject lines, excerpts, sender names, sender addresses, sender domains or attachment file names.

In the daily summary, message text does not leave the computer, but information about messages does, and that is personal data.

One exception: when the owner labels an individual message in Gmail as a newsletter to study or a class notice, the full text of that one message is sent to Anthropic so it can be analysed or turned into a calendar event. Receipts the owner labels are turned into a structured record (service, amount, dates) and written to the owner's own Notion subscription tracker.

Four third parties are involved overall — Google as the mail and calendar provider, Anthropic for classification, GitHub, which stores a pseudonymous migration register, and Notion, which holds the owner's subscription tracker. Nothing is sold, rented, or used for advertising.

The full list of third parties, what each one receives, what is removed before anything is sent, and the stated limits of those controls are in the Privacy Policy.
